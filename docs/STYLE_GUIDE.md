# STYLE GUIDE

Every lesson must follow these rules.

## Writing Rules

- Short paragraphs
- Bullet points preferred
- Maximum 150 words per section
- Beginner-friendly language
- Python examples under 20 lines
- Estimated reading time
- Difficulty level
- Importance level
- Assessment Tips
- Quiz at the end
- Cheat Sheet at the end

## Lesson Template (10 sections, in this exact order)

1. **Learning Objectives** — what the learner will be able to do after the lesson
2. **What is it?** — plain-language definition, no jargon
3. **Why is it important?** — why it matters for the assessment
4. **Key Concepts** — bullet-point list of the core ideas
5. **Python Examples** — short code blocks (≤20 lines) with brief notes
6. **Common Assessment Questions** — the kinds of questions to expect
7. **Common Mistakes** — frequent errors candidates make
8. **Quick Summary** — 3–5 bullet recap
9. **Quick Quiz** — 5–10 questions
10. **Cheat Sheet** — compact reference card

## Tone

- Direct and practical
- No academic tone
- No mathematical proofs
- No unnecessary theory
- "Learn wide, not deep"

## Code Style

- Python only
- Under 20 lines per example
- Use `import numpy as np` and `import pandas as pd` consistently
- Add a short comment or note under each code block

## Metadata (shown on every lesson)

- Estimated reading time (e.g., "12 min")
- Difficulty level (Beginner / Easy / Medium)
- Importance level (High / Medium)
- Assessment Tip (one practical tip per lesson)

## Quiz Rules

- 5–10 questions per lesson quiz
- 15–20 questions per mini test
- Question types: multiple choice, code reading, output prediction, short answer, MVP design
- Never LeetCode-style algorithm questions

## Mock Exam Rules

- 60 questions per mock exam
- 90 minutes (timed via `exam.timeMinutes`)
- Module distribution: A 25%, B 35%, C 25%, D 15% (A=15, B=21, C=15, D=9)
- Timed
- Per-module score breakdown
